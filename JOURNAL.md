**8/15/26 - I started designing**
So to start off the project I set up the repo, made a quick outline of how I want it to work, and made sure I knew what the requirements were. Then I started working on researching all the parts for the BOM, and I decided to use an ESP32-S3 mini version from seed studio for the main board(only 22mm tall) so I setup the rest of my components around that. I wanted the glasses to have good bone conduction transducers for audio, a heartbeat sensor for emotion analyzing, a camera for object and facial recognition, good mics for wake word detection and good input audio clarity, and plenty big batteries to make sure they would last the whole day. I researched and found each of the parts, then I set them all up nicely in the BOM right away for easy accesibility.

**8/17/26 - I started the CAD designs and pivoted my main objective**
The next thing to work on was the CAD designs for the 3d printed frame(maybe later even made in metal by PCBWay!). The first thing I did before even starting my designs was to look up different glasses styles, I really wanted these to have the right look, and be stylish along with functional. It took me a couple tries of redoing the design completely, until I liked how the front frames came out. A pretty classic glasses look, but slightly redone to fit my face better and work correctly. Then there were the arms of the frame. These were much harder, because they needed to be big enough to fit all the components, and still look like glasses not a VR headset. Ultimately I realized that the board I had selected really would just not work for a low profile glasses frame. The size was too tall, the pins slightly too limited, and the usability did not fit my asparations. So I made a risky decision; I would design my first ever custom PCB. I got to work right away on researching how it all works, I have never done one before so there was a lot to learn. I decided on the ESP32-S3 chip still, because it had built in camera support and things like that that really fit what I needed. Before too long I had the basic framework of how to start, and I decided to start work on the schematic. This was a very time consuming process, since I didn't know anything about the software I was basically looking up every single baby step. Before too long I had figured out some keyboard shortcuts and had the basic idea down, then it came to the portion of the process where I just needed to carefully add all the parts correctly and get them all wired. After working on it almost every waking second of my day, I managed to finish the basic schematic with all the components I would need.

**8/20/26 - I continued work on the custom PCB**
So now that I got the schematic for the PCB all set up, it was time to start the actual component placement. At first I pretty much just threw everything in a rectangle in a way that they all fit together as tightly as possible with little bits of extra room. Then when I went to run the traces I realized I had not optimized it very well at all, out of my 200+ connections, *only 23 could be made.* So I went back to the drawing board, I tried rearranging the components in a much better layout for the traces, and I did need to largely increase the size of the pcb outline to make it all seem to work better. And since it took so long for the PCB traces the first time, I ended up downloading the app freerouting, which is an auto-router for PCB traces. It did pretty well and jumped the connections up to 118, which was obviously closer but still not great. So I took that partially traced board back to KiCAD and tried to route the remaining traces myself. I managed to get a few more, but there were still wayyy too many unconnected pads. I went through this cycle another time or two, redesign, auto-route, manually route, fail. After it failing so many times I decided to try a different method, I realized that the most traces that were being left unconnected were 1. Ground and 2. The camera FPC connector to the esp32 chip. That made me realized that there must be a better way to connect all the ground pads, and that's when I learned what a ground pour was. I got that all setup and checked the connections, it managed to fix **31** connection issues. That was a huge help and a great motivation booster, that led me to keep trying orientation options for the remaining disconnections. I decided to try to position the esp32 chip directly next to the FPC connector for easy trace running, but really it just made the whole board as thick as the board I previously rejected. So I ditched that idea, and that's when I realized that if I slightly edited my original component placement in the glasses frames, I could make the PCB be by itself in one arm, leaving me almost 70mm of length to work with, as opposed to the 40 or so I had tried to cram in before. That was a game changer, and I was able to give each component much more room and also a cleaner setup in general. I reran the auto-tracing, and only 8 were disconnected! Those few were plenty simple to just route using a via or two that the automated program couldn't.
