# August 7: I made some basic drawings.
As usual for my projects I started off with some simple drawings of my idea, really the point of them is just to get a physical picture in my head before starting the true design process. Really the point of this whole build is to have a wearable device that I can use to communicate with my homebuilt, custom made transformer based AI: J.A.R.V.I.S. He also has tools and things to answer questions like weather, time, distances, facial recognition(through the camera), and more. For all of this, I decided to go with the Seeed Studio XIAO ESP32-S3 board, which is pretty small  and should work well. Then a couple other components that I know will be necessary, and I did a few renditions of the basic design to try to get a good style to fit what I was looking for, which I'm sure I will change more when I do the actual CAD of the project. For the most part these designs were simple, because the big benefit of small-scale projects is that there is literally just less area to manage. I also debated whether to go with some basic bluelight glasses lenses, or another simple option. Ultimately I decided that it would be slightly complex to try to model glasses frames around existing lenses, and really the point of these glasses is to be able to talk to J.A.R.V.I.S. when I'm AWAY from my computer, meaning bluelight would realistically not be needed.

# August 15: I started designing.
So to start off the project I set up the repo, made a quick outline of how I want it to work, and made sure I knew what the requirements were. Then I started working on researching all the parts for the BOM, and I decided to use an ESP32-S3 mini version from seed studio for the main board(only 22mm tall) so I setup the rest of my components around that. I wanted the glasses to have good bone conduction transducers for audio, a heartbeat sensor for emotion analyzing, a camera for object and facial recognition, good mics for wake word detection and good input audio clarity, and plenty big batteries to make sure they would last the whole day. I also wanted the lenses to be a simple clear polycarbonate, as discussed in the previous entry, since trying to build the lenses frames around other lenses would be quite difficult. After getting a basic idea for each of the parts, I researched and made sure it would all work, then that it would all work together, and got it all nicely formatted in the BOM.csv file.

# August 17: I started the CAD and pivoted my objective.
The next thing to work on was the CAD designs for the 3d printed frame(maybe later even made in metal by PCBWay!). The first thing I did before even starting my designs was to look up different glasses styles, I really wanted these to have the right look, and be stylish along with functional. It took me a couple tries of redoing the design completely, until I liked how the front frames came out. A pretty classic glasses look, but slightly redone to fit my face better and work correctly. Then there were the arms of the frame. These were much harder, because they needed to be big enough to fit all the components, and still look like glasses not a VR headset. Ultimately I realized that the board I had selected really would just not work for a low profile glasses frame. The size was too tall, the pins slightly too limited, and the usability did not fit my asparations. So I made a risky decision; I would design my first ever custom PCB. I got to work right away on researching how it all works, I have never done one before so there was a lot to learn. I decided on the ESP32-S3 chip still, because it had built in camera support and things like that that really fit what I needed. Before too long I had the basic framework of how to start, and I decided to start work on the schematic. This was a very time consuming process, since I didn't know anything about the software I was basically looking up every single baby step. Before too long I had figured out some keyboard shortcuts and had the basic idea down, then it came to the portion of the process where I just needed to carefully add all the parts correctly and get them all wired. After working on it almost every waking second of my day, I managed to finish the basic schematic with all the components I would need.

# August 20: I continued work on the custom PCB.
So now that I got the schematic for the PCB all set up, it was time to start the actual component placement. At first I pretty much just threw everything in a rectangle in a way that they all fit together as tightly as possible with little bits of extra room. Then when I went to run the traces I realized I had not optimized it very well at all, out of my 200+ connections, *only 23 could be made.* So I went back to the drawing board, I tried rearranging the components in a much better layout for the traces, and I did need to largely increase the size of the pcb outline to make it all seem to work better. And since it took so long for the PCB traces the first time, I ended up downloading the app freerouting, which is an auto-router for PCB traces. It did pretty well and jumped the connections up to 118, which was obviously closer but still not great. So I took that partially traced board back to KiCAD and tried to route the remaining traces myself. I managed to get a few more, but there were still wayyy too many unconnected pads. I went through this cycle another time or two, redesign, auto-route, manually route, fail. After it failing so many times I decided to try a different method, I realized that the most traces that were being left unconnected were 1. Ground and 2. The camera FPC connector to the esp32 chip. That made me realized that there must be a better way to connect all the ground pads, and that's when I learned what a ground pour was. I got that all setup and checked the connections, it managed to fix **31** connection issues. That was a huge help and a great motivation booster, that led me to keep trying orientation options for the remaining disconnections. I decided to try to position the esp32 chip directly next to the FPC connector for easy trace running, but really it just made the whole board as thick as the board I previously rejected. So I ditched that idea, and that's when I realized that if I slightly edited my original component placement in the glasses frames, I could make the PCB be by itself in one arm, leaving me almost 70mm of length to work with, as opposed to the 40 or so I had tried to cram in before. That was a game changer, and I was able to give each component much more room and also a cleaner setup in general. I reran the auto-tracing, and only 8 were disconnected! Those few were plenty simple to just route using a via or two that the automated program couldn't.

# August 25: I updated the CAD with the new parameters.
Now with me deciding to go the custom PCB route I had a lot more flexibility in the glasses frames. So I worked through a couple options for the arms, and initially I was just going to have the whole arm be about 16mm thick to fit the PCB. But after looking at it and comparing I decided to go with a curved bottom and slightly slanted top, which would allow the PCB plenty of room and still keep the arms relatively thin. At first the arms ended up being still almost 20mm wide, which was the exact thing I was trying to avoid by creating the custom PCB. So I messed with the PCB a bit to shrink it down a bit, and was able to get the arms down to 19mm at the smallest point, which still was not ideal. Then I took a step away from it for a bit, and when I went back I realized that somehow I had completely misread the PCB specs thinking it was 17mm, when it was actually *13.75mm* that meant I could shrink the arms width down exponentially, getting the largest part of the arm down to about 16mm. This made the whole look a lot cleaner and really made the whole design work better too.

# August 30: I tested some new printing techniques.
So I wanted to get a good idea of how to print each piece, so I threw some in the slicer to do a quick print. For the lenses frames I started out by putting them face down on the plate for printing ease. I went through a couple testing models with the arms attached differently to try to get a good idea of how to secure them for maximum stability and clamping force for the sensor and transducers. Most of these test were also done in between the versioning of the arms, as discussed in the previous journal entry, meaning most of these test were done with the thicker arms. After a couple tests, I determined that the best way to have the body of the arms open to insert the components was to make one side with the extruded walls, and the other as a flat piece on the outside for looks. Then I checked out a couple versions with an ironed top, which really gave them a clean look. I also ended up deciding to go with a carbon-fiber PETG for the frames, as this would give a great strength to weight ratio, plus the carbon fiber added really helps remove layer lines for that nice clean 'machined' look. Ultimately I did need to do some slight mods to the lenses frames to make them look better with the arms, and to add the camera hole and remove the curve to get that nice ironed look.
Then I also added whatever the parts are called on the frames that rest against the sides of your nose, actually let me look up what those are called quick, hold on...Okay I'm back, apparently they are just called 'nose pads' which is wayyy too generic of a name in my opinion, a part like those is exactly the kind of thing that should have some ridiculous name that makes no sense and has no origin. Anyways I designed those as separate pieces to glue on, because if they were attached then I wouldn't be able to print the glasses flat down meaning they couldnt be ironed and look nicer.

# September 4: I exported the PCB and configured it in JLCPCB.
So now that the PCB was designed, I went ahead and exported it to add to JLCPCB to see how it all imported. It wasn't too hard to learn how to export the gerbers, BOM, and CPL files but it did take a little bit of research to make sure I got everything right. After that I just uploaded them all into jlc to check requirements and pricing. This is when I realized that they would not be able to add the electret mic, so I would need to hand-solder that. So I removed it from my PCB BOM and found a suitable replacement on SameSky. The total ended up being MUCH more than I anticipated, which really meant I had to get the board perfect the first time, so I didn't need to spend hundreds of dollars on iterations. Thankfully I do have some first timer coupons so that will help with the cost, but it was still steep enough that I decided to also upload it to PCBWay to see if their prices were any better, but it ended up being probably a bit more. However, after I put the board in my cart within a few hours I got an email from them explaining how there were a few errors with my design. This was super helpful as a first time PCB designer I really didn't know some things(I had put some vias in the SMD pads which apparently is a no-no). So I spent a little bit moving all of those to make sure there would be no shorts, then I just ran DRC and fixed all the errors. And while doing that switch around, I happened to notice that I had accidentally used the wrong footprints for the MAX98357A, so the chips would not actually fit on the pads when JLC went to assemble it. That just meant replacing the footprint in the schematic, and then rewiring it. It wasn't too complicated of a process and that part was done pretty quickly. Then came the PCB. Unfortunately the updated footprints were much larger than their predecessors, meaning there would need to be a lot of reworking to get them to fit. I had to move R3, R1, and R5 around a little bit to make sure the pieces would fit, and I managed to get them squeezed in there eventually. Unfortunately that left almost no room for the traces, and it took FOREVER to route them all, and try to get them to connect correctly, and add more vias to get everything to work. Eventually I got all the pads connected, arguably with way too many vias but who's keeping track? Then I ran DRC, and found about 30+ errors to fix. Most of them were simple tolerance issues, meaning I just had to slide a trace over or shift a via. After a little bit of work I got them all sorted out, and I went to edit the BOM to ensure everything was up to date. That's when I realized that I had completely forgotten to add an antenna connector. This also was not too complicated, and before too long I had researched and found the right part, and then I just threw it in the schematic, rearranged some traces and components, and had it all set up.

# September 6: I fixed the VCC-GND short.
Today was the day to finally fix the VCC net that I discussed in the previous journal entry, basically all the VCC pads were connected to ground. This was a huge undertaking, and it started back in the schematic. Turns out, while I was setting up power flags, I had accidentally connected ground and VCC to the same one, I thought they were both the same type connecting so it didn't matter, but I was wrong. Obviously this part was a simple fix that went great and I had no problems with, but it caused more than a few issues in the PCB. However, before I went to that I did make sure to do a couple once-overs of the schematic and make sure it looked fine, and ran ERC again to confirm there were no obvious issues(somehow I missed that last time). Then I realized that I hadn't actually added a step down convertor for the power, so I also had to throw in one of those to make sure there were no issues with that. It wasn't too hard, just adding it in and relabeling a few things, and since I already needed to reroute like 50 traces or something it wasn't a big deal to add 2 or 3 more. So then came the part that was not necessarily hard, but most certainly time consuming. The first part of rerouting I did was just to disconnect all the VCC pads from ground, which didn't take too long since I disconnected those wires in the schematic, so DRC just showed all the shorts. Then I started my run of reconnecting all those disconnected pads to the VCC net(and some to the new VBAT net which was just the power without the step down converter. When I say this took a long time, I mean I pretty much spent 6 hours across a weekend trying to get all these traces rerouted. Which was a lot harder to do with the updated VCC and VBAT nets, since when I had accidentally done them with ground they basically just made one HUGE net that was easy to connect to since it was everywhere. But honestly running traces and doing the PCB side of designing a PCB is one of my new favorite things to do, getting to manually work things around, find paths, move things, constantly refactor, and all of that is so rewarding, even if it can be upsetting at times. Really the only big actual issues I had were running the VBAT traces to the freshly updated MAX98357A modules, which were pretty tight in the new version, and the right one was extremely close to the border. I ended up needing to move the left one up and to the left a bit, then move the right one over to the left some, in order for me to be able to run the VBAT traces to each of the required pads. Then I did also need to completely reroute the traces from J4 up top, which was mostly just trial and error of finding the right path for a while. I finally got them both reconnected, then went back to the VCC and VBAT running. There were a multiple times where I had to slide like 4 traces in the same direction in order to run a new one through, which definitely did leave some traces slightly twisted around, but ultimately I realized the point of this PCB is to 1. Learn everything I am learning, and 2. Have a WORKING PCB, not necessarily a pretty one. After I got all the traces ran, I tested DRC, which gave me no less than 31 errors. Most of them were just clearance violations(probably due to the trace shoving mentioned a second ago) and were pretty easy to just scootch around until they fit correctly. There were also a couple that were issues with GND being isolated, so I did need to do some more trace running to fix all of those. Ultimately I got it all fixed, and you can be sure I will never be connecting VCC and ground again, even by accident.
